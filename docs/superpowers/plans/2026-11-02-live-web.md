# Live Game Page (web) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `/live` to the static Next.js site: a client-side page that reads the ESPN public API in the visitor's browser and shows scorebar, court with possession, team comparison and box score.

**Architecture:** Pure TypeScript parsing/derivation modules in `web/lib/live/` (no React, TDD with `node --test`), presentational components in `web/components/live/`, one client hook that fetches and polls, one static page shell. Team clash colours are computed in Python and exported into `web/tokens.json`.

**Tech Stack:** Next.js 15 app router, React 19, Tailwind 3 with generated tokens, TypeScript 5.9, Node 24 built-in test runner (type stripping), Python 3.13 + pytest for the colour export.

**Spec:** `docs/superpowers/specs/2026-11-02-live-web-design.md`

## Global Constraints

- No new npm or Python dependency.
- No hex colour literal in any `*.ts*` file under `web/app`, `web/components`, `web/lib` (gate `test_no_hex_literals_in_the_web_app`); colours come from Tailwind token classes or `web/tokens.json`. Hex literals are fine in `web/tests/`.
- Modules in `web/lib/live/` import each other **only with `import type`** (erased at runtime), so `node --test` never has to resolve a runtime import between them. Only erasable TypeScript syntax there (no `enum`, no `namespace`, no parameter properties).
- Data source: ESPN only. `https://site.api.espn.com/apis/site/v2/sports/basketball/nba/scoreboard[?dates=YYYYMMDD]` and `.../summary?event=<id>`.
- Code, comments and UI copy in English. Away team always on the **left**, home on the **right** (scorebar, court, comparison).
- Parallel agents share one working tree: **agents do not run git**, edit only the files their task lists, and run only their own test file (`node --test tests/live/<file>.test.ts` from `web/`). The coordinator commits after each task's review.
- Fixtures already exist (uncommitted) in `web/tests/fixtures/`, captured 2026-11-02 and trimmed to `header`/`boxscore`/`plays`:
  - `espn-summary-final.json`: game 401909903, BOS @ ORL, final 108–97.
  - `espn-summary-live.json`: same game cut after play seq 445 (Q3 4:58, 69–59). Status set to `in`, possession flag `true` for BOS.
  - `espn-summary-pre.json`: scheduled, no plays, empty box score.
  - `espn-scoreboard-today.json`: `day.date` 2026-11-02, 15 scheduled games.
  - `espn-scoreboard-2026-11-01.json`: 4 finals, no `day`.
  - **Do not re-download them**: the expected values below were computed from these exact files.

## Review Focus

1. **ESPN payload missing pieces** (pre-game: no plays, empty `boxscore.players`; a player with `stats: []`): parse to empty arrays / empty cells, never throw. Pinned in Task 1 (`pre` fixture, DNP rows) and Task 5.
2. **Overtime** (period 5+): labels `OT`, `2OT`; team fouls counted for the current OT period. Pinned in Task 6 (`periodLabel`) and Task 4.
3. **Malformed substitution** (missing `participants`, unknown team id, a player leaving who is not on court): ignored without throwing. Pinned in Task 3.
4. **Matchup key order**: overrides are keyed by sorted tricodes, but the page looks them up as home/away. `HOU` home vs `CHI` away must still find `CHI-HOU`. Pinned in Task 6.
5. **Refresh failure mid-game**: keep the last data and show the stale banner, never a blank page. Owned by Task 10 (hook) and checked by hand in Task 11.

**Interfaces — Produces:** `useLiveGame(): { status: "loading" | "ready" | "empty" | "error"; games: ScoreboardGame[]; selectedId: string | null; select: (id: string) => void; summary: GameSummary | null; updatedAt: number | null; stale: boolean }`

Hook behaviour, decided by the spec:
1. **On mount:**
   - read `?game=` from `window.location.search` (no `useSearchParams`, so no Suspense is needed);
   - `fetchScoreboard()`; if `needsPreviousDay` and `day` is non-null, also `fetchScoreboard(previousDayParam(day))`;
   - `games` = previous plus today, sorted by `startTime`;
   - `pickGame` → selected id; `status` is `"empty"` when it is null.
2. **Summary:** fetch it for the selected game unless that game is `pre`.
3. **Polling:** decide **once, on the initial scoreboard**, with `shouldPoll(today)`. If true:
   - every 30 s, refetch the scoreboard and, when the selected game is `in`, its summary;
   - skip ticks while `document.hidden`, and on `visibilitychange` back to visible run a tick right away;
   - stop for good once a refreshed scoreboard has no `in` game.
   If false, never set an interval.
4. **Refresh failure:** keep the previous data, set `stale = true`; the next success clears it. A failure of the **initial** load → `status: "error"`, with a "Couldn't reach ESPN — try again later" message.
5. **`select(id)`:** set it, `history.replaceState(null, "", \`?game=${id}\`)`, fetch the summary (unless `pre`).
